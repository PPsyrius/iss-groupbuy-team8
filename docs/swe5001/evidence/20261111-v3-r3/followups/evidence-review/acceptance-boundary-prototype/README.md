# Acceptance-boundary prototype — proposal only

**Not installed, not a new historical acceptance rule, and not R4 authorization.** All changes are confined to this new directory. `boundary.mjs` performs pure deterministic checks over supplied byte snapshots; `boundary.test.mjs` contains explicitly synthetic, non-live fixtures. The one real-data regression reads only R3 summary/observer/observations and the existing coverage projection from read-only mounts; it neither modifies metrics nor reads/copies the 2.6-GB raw stream.

## Verification

Docker `node:24-bookworm`, runtime **v24.22.2**, `--pull=never --network none --read-only`: **130 tests passed, 0 failed**, exit **0**. One test exhaustively checks **256** true/false combinations of collection/coverage flags, allowing only all-true plus otherwise valid evidence. Exact command and child status are retained in `test-receipt.json`; TAP stdout/stderr are retained separately. No packages, host Node/Java, cloud calls or workload traffic were used.

## Exact proposed checks

1. **Original collection semantics:** `collectionComplete === true`, `timerCompleted === true`, `errors` explicitly an empty array, integer sample count at least two and equal to actual JSONL rows. Recompute strictly positive ordered observation gaps **≤45 seconds** and coverage bracketing the summary-derived execution interval, with equal endpoints permitted as in the original analyzer. Validate receipt maximum gap against rows. No new maximum campaign age, preflight-age rule or workload-duration threshold is introduced.
2. **Coverage consistency:** explicit true collection/timer/bracketing/gap/count/maximum-gap-match flags, empty preserved collector errors, exact row count, first/last instants and maximum gap. Claimed true flags cannot substitute for recomputation. UTC timestamps retain nanosecond precision, so `45s + 1ns` is rejected rather than truncated; R3's microsecond gap is verified exactly.
3. **Future normalization contract:** `schema=1`, `contract=proposed-boundary-v1`, `completed === true`, numeric `exitCode === 0`, and explicitly present empty `normalizationBlockers` in both receipt and event output. Match run, base commit, manifest digest, execution digest, exact event-output digest, and the actual source bytes/hash of a manifest-listed normalizer. A successful shell exit alone is insufficient. Event semantics remain owned by the unchanged analyzer; the prototype does not fabricate or normalize activities.
4. **Full declared executable identity:** independently pinned run/base/source-state, execution SHA-256, manifest SHA-256, evidence digests, and reviewed source inventory. The manifest must match the exact inventory, roles, file lengths, and SHA-256 of supplied executable/dependency bytes, including analyzer, collector and normalizer roles. Bind execution and normalization to that manifest. Missing dependencies, substituted sources, stale runs, unexpected artifacts, wrong roles, and relabelling an uncommitted bundle as committed are rejected. A base commit alone is never sufficient.
5. **Fail-closed shapes:** missing/null/string/numeric booleans, missing or malformed arrays/counts/hashes/JSON, partial/all-false flags, stale windows, duplicate/reversed timestamps, and mismatches are refusals. Unknown is not zero. Exact hash matching uses supplied bytes rather than a reserialized JSON representation.

`reviewCollection()` returns collector-boundary diagnostics only. `reviewBoundary()` can return `canInvokeUnchangedAnalyzer=true` for a completely bound **synthetic** bundle, but always returns `httpGatesEvaluated=false`, `acceptanceComplete=false`, and `launchAuthorized=false`. The positive fixture deliberately has synthetic drops and no real AWS preflight/events: permitting the next validation stage is **not** an HTTP pass. No linearity, database/generator headroom, final-deployment or dashboard result is inferred.

## Integration sketch — future implementation only

1. Before an independently authorized future campaign, review/pin a complete executable/dependency manifest, source state and execution receipt. Record changed executable hashes separately from the base commit; `uncommitted-on-base` is supported without claiming the base SHA identifies those bytes.
2. Preserve original collector, summary, raw observations and successful/failed normalization output. A future normalization receipt records completion/exit, explicit blockers, exact output digest and source/execution binding. The coverage receipt must preserve failure state and be validated against actual rows.
3. A separate wrapper reads immutable snapshots, takes its trusted anchors from an independently reviewed source, and calls this boundary. On refusal, retain the diagnostic outcome and stop acceptance processing. On permission, invoke the **same hashed analyzer** with its existing four arguments: original summary, original samples, original observations and normalized events. Preserve actual analyzer stdout/stderr/exit; do not suppress or change its HTTP/drop/latency/arrival/task-count gates.
4. Preserve the original analyzer's limited result and outstanding independent criteria. Use immutable/read-only inputs to prevent a check/use race. Raw-sample integrity and the existing campaign manifest remain separate requirements; this small prototype intentionally does not scan raw samples or execute the analyzer.

Older campaigns lack the proposed complete source/normalization contract. **Do not add fields to sealed receipts, invent a normalization success record, or reclassify historical outcomes.** Historical evidence can be reviewed under its actual recorded contracts; this prototype is a proposed future boundary, not a retroactive evaluator. The R3 regression exercises existing collector failure semantics only, and confirms incomplete collection despite valid successful-sample spacing/bracketing.

## Owner decisions and limits

- **New canonical contract needed:** no existing canonical contract supplies this exact executable manifest/inventory, independently trusted anchor, or source-bound completed-normalization receipt. Approve/version the schema, writer and custody/trust model before implementation. This prototype calls its artifact `execution.json` only for future fixtures; existing campaign execution receipts are not rewritten to match it.
- **Completeness/truth are not proved by hashes:** the owner must approve the full source dependency closure and exact analyzer/normalizer invocation path. A self-consistently forged bundle can pass if an untrusted caller is allowed to replace its own “trusted” anchors. Hash agreement does not prove that the claimed collector or normalizer actually ran those bytes; execution custody/attestation is outside this pure function.
- **Coverage contract needs ratification:** approve required fields, exact UTC/precision serialization and receipt-to-row binding. The 45-second positive-gap and bracketing requirements come from existing rules; strict schema/precision/source-binding fields here are explicitly future-contract proposals, not previously applicable historical thresholds. “Stale” means wrong run, source hash, output binding or execution coverage—not an invented wall-clock age limit.
- **Not complete acceptance orchestration:** no live CLI, trusted-anchor generator, signature system, normalizer implementation, AWS collection, repository integration, raw stream audit, whole-application source audit, or acceptance override was added. The unchanged analyzer still owns task/deployment/preflight/raw/HTTP checks; independent evidence still needs human review. A later canonical implementation requires separate code-change authorization.
