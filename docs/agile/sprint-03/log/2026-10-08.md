## 2026-10-08 - @EricWang1358 - Resolve the invite sharer before the team row lock (#276)

- Kind: nfr (performance, concurrency); refs [#276](https://github.com/PPsyrius/iss-groupbuy-team8/issues/276), NFR-53.
- Changed: `PurchaseIntentAppService.join` calls `resolveSharer` before `lockJoinTerms`, so a JOIN that carries an invite reference no longer holds the team row while it waits on the Redis read (and, on a miss, the PostgreSQL read and Redis write). `resolveSharer` reads only the immutable invite row, takes no lock and never rejects, so the error a client sees is unchanged; a JOIN the lock then refuses pays one extra lookup. A JOIN without a reference, START, lock order, the 10 s transaction timeout and event ordering are unchanged.
- Verified: JDK 21.0.4 `./mvnw -B verify -DskipITs` passed all seven modules (1394 unit tests: domain 440, application 456, adapter 14, infrastructure 237, bootstrap 247; zero failures; Spotless, Checkstyle, SpotBugs and ArchUnit clean). `PurchaseIntentAppServiceTest` gains 16 cases (43 in the class) pinning lookup-before-lock order, the team's refusal winning for every `lockJoinTerms` error whether or not the reference attributes, and an unchanged no-reference JOIN. Run against the previous ordering, 12 cases fail (these new cases plus the flipped `InOrder` assertion).
- Not verified: the `*IT` classes (no Docker daemon in this environment, left to CI) and any measured lock-hold or p95 change (none claimed). Contract unchanged: no controller or DTO touched, `contracts/openapi.json` not regenerated.
- Decisions: none new; one sentence added to the [invite-ref cache design](../../../../backend/docs/design/invite-ref-cache.md) and the [NFR-53](../../../quality/nfr-register.md) row extended, as the ordering is a property of the same lookup.
- Next: if the #180 load test shows contention on `lockJoinTerms`, measure join-intent p95 before and after against that baseline.

## 2026-10-08 - @EricWang1358 - Catalog browse and detail release the database connection before the best-offer lookup (#275)

- Kind: nfr (performance, availability); refs [#275](https://github.com/PPsyrius/iss-groupbuy-team8/issues/275), a follow-up to the best open-deal cache; branch `feature/perf-catalog-release-connection`.
- Changed: `ProductAppServiceImpl.pageListings` and `getListingDetail` lost their method-level `@Transactional(readOnly = true)`; only the product reads (`pageOnSale`, `findById`) now run in a read-only `TransactionTemplate` that commits before `findBestOpenDealsByProductIds`, so a stalled Redis lookup (3 s command timeout) no longer holds one of the 10 Hikari connections per browse or detail request. `search()` is untouched and was already non-transactional.
- Behaviour: responses, ordering and error codes are unchanged and there is no HTTP surface change, so `contracts/openapi.json` is unchanged. No code in either method relied on one snapshot: the default isolation is READ COMMITTED, the product page and count statements already had separate snapshots, and the offers are cached display data.
- Verified: `./mvnw -B verify` on JDK 21.0.4 with the local Docker daemon (images `postgres:18`, `redis:8.10`) passed, BUILD SUCCESS in 7 min 11 s: 1,613 tests run (440 domain, 444 application, 14 adapter, 237 infrastructure, 247 bootstrap unit, 58 infrastructure ITs, 173 bootstrap ITs), 0 failures, 1 pre-existing skip; Spotless, Checkstyle (0 violations), SpotBugs (0 bugs in every module) and `ArchitectureTest` (8) are green.
- Verified: four new `ProductAppServiceImplTest` cases (19 in the class) use Mockito `InOrder` to prove the read-only transaction is opened, runs the repository read and commits before the deal lookup on both paths, and that a missing product or a failed read skips the lookup (commit or rollback as appropriate); `CatalogListingProgressIT` (3) and `BestOpenDealCacheIT` (11) still pass; the JaCoCo aggregate shows no missed line or branch in `ProductAppServiceImpl`.
- Not verified: CI (`build-quality`, `contract-check`, SonarCloud) runs only on the PR. No load test or Redis-stall fault injection was run, so the connection-pool benefit is established by construction and ordering tests, not measured.
- Decisions: recorded in the existing [best open-deal cache design](../../../../backend/docs/design/best-open-deal-cache.md) (the outer catalog transactions no longer wrap the lookup), no new ADR; NFR-41 in the [register](../../../quality/nfr-register.md) extended, no new row.
