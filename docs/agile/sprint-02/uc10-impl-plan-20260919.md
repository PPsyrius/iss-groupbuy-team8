## 3. PR-2 — Order 聚合行为化(对应计划 9/16;Payment 聚合归 Yorik)

### 3.1 OrderStatus / Order

`com.blocbuy.order.model.OrderStatus`:枚举 `PENDING, CONFIRMED, CANCELLED` + `canTransitionTo` 判断(状态机内聚,Service 禁 if/else 判状态)。

`Order` 字段:`id, orderNo, paymentId(去重键,来源 Yorik 的 Payment 聚合 id), dealId(Optional), userId, productId, productTitle, productImage, quantity, unitPrice(BigDecimal), totalAmount, currency, status, paidTime, cancelTime, version`。

行为(替换现有 placeholder,保留"出生即合法"工厂风格):

```java
public static Order create(...)                 // 工厂:校验 amount>0、quantity>0、totalAmount=quantity*unitPrice
public Order confirm(Instant now)               // PENDING→CONFIRMED;否则 BizException(OrderErrorCode.ORDER_ILLEGAL_TRANSITION)
public Order cancel(String reason, Instant now) // PENDING→CANCELLED;记 cancelTime
public Order reconstitute(...)                  // 仓储重建用,包内可见或同包
```

- 金额不复用 `GroupDealMoney`(groupbuy 包内部聚合,跨域访问违规)→ 直接 `BigDecimal` + `currency` 字段
- 快照字段 `productTitle/productImage` 落库,后改商品不改历史(UC9 风险)
- 无 `setStatus` / `@Data`;不可变风格,transition 返回新状态快照或 this 内部变更,照 `GroupDeal.joinPaid` 惯例
- Order 只引用 `paymentId`(UUID),不 import Payment 聚合 → 与 Yorkin 工作零编译耦合

`OrderErrorCode` 补码:非法迁移、订单不存在、并发冲突(或挂 `CommonErrorCode.CONFLICT`,先看现有枚举,缺则补)。禁自由字符串异常。
