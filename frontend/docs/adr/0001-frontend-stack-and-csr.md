# 0001. Frontend stack and pure CSR

Date: 2026-09-16

## Status

Accepted

## Context

`frontend/` was empty until Sprint 2. The dev edge already exists and is hand-built: CloudFront
serves `/` from a private S3 bucket (OAC) and `/api/*` from the backend ALB, so the SPA and the
API share one origin (`https://d1b3np88z657cp.cloudfront.net`). Nobody on the five-person team
operates a Node runtime in any environment, and the backend pipeline only ships static files to S3.
Most frontend code is written through coding agents, so the stack has to be one whose types,
generated code and lint rules catch mistakes an agent makes. The blueprint (revision 2, 2026-09-15)
settled the stack; the plan (2026-09-16) re-verified every pin against the npm registry. The
browser floor is Tailwind 4's baseline: Safari 16.4+, Chrome 111+, Firefox 128+ (recorded as an NFR).

## Decision

The frontend is a pure client-side React 19.3.0 SPA built by Vite 8.3.0 (Rolldown) into static
files. TanStack Router 1.170.36 owns URL state and auth guards, with file-based routes generated
by `@tanstack/router-plugin` 1.168.38 (listed before the React plugin). TanStack Query 5.102.8
owns server state through the generated client (ADR 0003, ADR 0009). TanStack Form 1.33.5 and
valibot 1.5.0 appear at exactly two hand-written boundaries: `validateSearch` schemas and form
schemas. Styling is Tailwind CSS 4.3.3 with HeroUI 3.2.5 over raw React Aria Components.
TypeScript is 7.0.2 (`tsc` entry point). React Compiler is on (ADR 0010); no manual `useMemo`,
`useCallback` or `React.memo`. All pins are exact, no caret ranges (ADR 0013).

Alternatives rejected: TanStack Start or Next.js SSR (needs a Node runtime the team does not
operate; S3 + CloudFront is already built); Vue/Nuxt (team skill); raw React Aria over HeroUI
(more styling work); `@tanstack/react-table` now (deferred to #31 and evaluated in T2-09, which
writes its recommendation as an addendum here).

## Consequences

`src/routeTree.gen.ts` is generated by the router plugin and committed as read-only output, so
`tsc --noEmit` works on a fresh clone before Vite has run; it is excluded from oxlint, oxfmt and
knip (plan §12 note 16, T1-05, 2026-09-16). `autoCodeSplitting: true` is set explicitly because
the plugin defaults it to `false` (note 11). Route loaders warm the cache with
`queryClient.query({ ...options, staleTime: 'static' })` because Query 5.102 deprecates
`ensureQueryData` (note 2). HeroUI needs no provider and no Vite plugin, only two CSS imports in
order (note 10). Because HeroUI's `Button` wraps react-aria-components' `Button`, which has no
`href`, the header's login control is HeroUI `Link` + `buttonVariants` (note 27, T1-11 `828d48b`).

T1-05 (2026-09-16) verified the scaffold: `vite v8.3.0` built 240 modules in 548 ms into
`dist/index.html`, four JS chunks and a 435 kB CSS bundle; `/` and `/does-not-exist` rendered in
headless Chrome with zero page errors. Open, parked by the 2026-09-17 branch review: the TanStack
devtools ship in the production bundle and `build.sourcemap: true` publishes full source maps;
resolving that needs a decision before T1-14 (ADR 0004 carries the runtime-config constraint).
