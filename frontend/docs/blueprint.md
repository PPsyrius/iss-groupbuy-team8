## Settled decisions (do not reopen)

**Sequencing**
- Full toolchain first, then the demoable slice, both within Sprint 2. Order the plan by dependency, then by risk: CloudFront `/api` behavior and auth wiring are validated earliest.

**Runtime and build**
- React 19.3, pure CSR. TanStack Router with `@tanstack/router-plugin` (file-based routes) + Vite 8 (Rolldown), built to static files, deployed to the existing hand-built S3 + CloudFront.
- React Compiler ON via `@vitejs/plugin-react` 6 with Babel and `babel-plugin-react-compiler` 1.0.0. `@vitejs/plugin-react-oxc` is deprecated; the native `react({ compiler: true })` path is experimental and is a tier-2 experiment, not the baseline. Convention: no manual `useMemo` / `useCallback` / `React.memo`.
- TypeScript 7.0.x (Go compiler, `typescript` package, `tsc` entry point). 7.0 has no programmatic API until 7.1; any tool needing the compiler API uses `typescript@npm:@typescript/typescript6`.
- Tailwind CSS 4.3. Browser floor is Tailwind's baseline (Safari 16.4+, Chrome 111+, Firefox 128+); record as an NFR.
- HeroUI 3.2.x (`@heroui/react`, on React Aria Components 1.21, requires Tailwind v4). Pin exact versions, no caret ranges.
- pnpm 12 pinned via `packageManager` + Corepack. Node 24 LTS pinned via `mise` (`.mise.toml`) and `.nvmrc`; Corepack is not bundled from Node 25.

**Data and validation**
- TanStack Query 5 for server state.
- `@hey-api/openapi-ts` 0.99.x generates the client from `contracts/openapi.json` with the valibot plugin (response schemas), the TanStack Query plugin (`queryOptions` / `mutationOptions`), and the MSW plugin (handlers). Pin exactly.
- Client config overrides `baseUrl` to `/` because the committed spec's `servers[0].url` is the export harness `http://localhost:18080`.
- Every JSON response is a `Result<T> {code, data, message, errors?, traceId?}` envelope. Keep the generated envelope types; unwrap `data` in one shared `select` helper; throw on non-2xx or non-OK `code`. Do not add a generator transform.
- Generated client is NOT committed. `pnpm gen:api` runs in `prepare` and as the first step of `pnpm check` and `pnpm build`; output directory is gitignored (add the entry; none exists) and excluded from oxlint, oxfmt, and knip.
- valibot at two hand-written boundaries only: TanStack Router `validateSearch` (Standard Schema) and forms. Never hand-write schemas for API responses.
- Forms: TanStack Form 1.x (Standard Schema). Settled; do not evaluate alternatives.
- MSW 2 handlers are generated by hey-api, loaded in Vitest `setupFiles` and behind a dev flag.

**Networking and auth**
- CloudFront serves the SPA at `/` (S3 origin, OAC) and the backend at `/api/*` (ALB origin, `X-Origin-Secret` header). Same origin, no CORS; the backend has zero CORS config, so same-origin is a hard requirement. Dev URL: `https://d1b3np88z657cp.cloudfront.net`.
- The backend has no context path. `/api/v1` is carried by controller mappings; actuator is at `/api/actuator`. CloudFront does not rewrite paths.
- Auth is Google OAuth only, via Sa-Token 1.46. Login is a full-page navigation to `GET /api/v1/auth/oauth2/google` (302 to Google). The callback sets the `blocbuy-token` cookie (HttpOnly, SameSite=Lax; Secure pending B3). Session probe is `GET /api/v1/auth/me` (returns `{loginId}`; enrichment pending B4). Logout is `POST /api/v1/auth/logout`. Unauthenticated requests get JSON 401 in the envelope; `GET /api/v1/products/**` is anonymous.
- Auth state: a `useSession` query over `/auth/me`, a 401 interceptor on the generated client that clears the session query and never redirects, and `beforeLoad` guards in TanStack Router reading auth from router context. Only guards redirect.
- Post-login return to the SPA depends on backend ask B1 (callback 302 to `/auth/callback`). Until it lands, treat it as the top blocker and plan the route anyway.
- Local dev: `docker compose up` at the repo root gives the backend on `http://localhost:8589`; Vite `server.proxy` maps `/api` to it with the prefix preserved. The `docker` profile sets the cookie non-Secure so plain HTTP works.
- No `VITE_*` environment variables. One build artifact is promoted dev → prod unchanged. Any future runtime config is served as `/config.json` with `no-cache`.

**CloudFront and deploy (hand-managed; coordinate via the runbook, not `infra/`)**
- `/api/*` behavior already matches: managed `CachingDisabled`, `AllViewerExceptHostHeader`, all seven methods. Default behavior: `CachingOptimized`, GET/HEAD, compress.
- SPA fallback via a CloudFront Function on the default behavior's viewer-request (extensionless paths → `/index.html`). Documented as optional in `docs/deploy/dev-cloudfront-deployment.md` §7.3 and not known to be attached; the plan adds a runbook step and a verification. Do NOT use distribution-wide custom error responses.
- Response-headers policy for CSP and HSTS: does not exist; runbook step to add.
- Cache headers set at `aws s3 sync` time: hashed assets `max-age=31536000, immutable`; `index.html` `no-cache`. Invalidate `/index.html` on deploy. Runbook §10 already prescribes this but says `npm`; update to pnpm.
- Deploy from CI: `deploy-s3-dev` job on push to `dev`, gated by a `frontend-dev` GitHub environment and `ENABLE_S3_DEPLOY`, assuming an OIDC role created via the runbook (policy examples under `deployment/frontend/iam/`).
- Terraform import of the frontend edge (`infra/terraform/frontend-stack/`) is a tier-2 task in Sprint 2, linked to #48. Not a gate for the walking skeleton.

**Quality toolchain**

- Lefthook pre-commit: oxfmt, oxlint, typecheck on staged files.
- Dependabot (not Renovate): add an `npm` ecosystem for `/frontend` to `.github/dependabot.yml` with `tanstack` and `heroui` groups, daily like the others.
